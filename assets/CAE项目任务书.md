# CAE 项目任务书

## 第一部分　工程师输入概要

项目名称　〔AI 代填〕

你可以交一份现成的项目书，也可以直接和 AI 交谈。AI 会把资料和答复整理在这一页。你可以随时补一句话、指一张图或改一处记录。

**工程处理流程**　几何建模 → 几何清理与理想化 → 网格划分 → 物理建模 → 求解 → 结果处理与报告

**工具选择**　各环节有指定的软件吗？已有模型可直接沿用。简单几何和小型验证算例默认在 Abaqus 中建模，复杂结构或多零件装配默认推荐 SOLIDWORKS，其余未指定的环节默认用 Abaqus。

### 一、分析目的

〔AI 代填〕本次分析要支持的决定或要解释的现象。AI 可从原话代拟各指标需要的精度，摘录已有验收条件与时间预算。

### 二、分析对象与已有资料

〔AI 代填〕分析对象、资料及其版本。可直接采用工程师提供的材料牌号、产品型号或图中标记。

**单元类型**　〔已有指定时记下适用部位、求解器和原要求。如委托 AI 选择，在这里简列拟用类型并标为待确认。〕

### 三、实际工况

〔AI 代填〕对象怎样安装和工作，本次要分析哪些情形。保留已知数值、单位和方向。

### 四、报告需要回答的问题

〔AI 代填〕工程师关心的结果、比较对象和已有判据。

**场输出**　〔需要看哪些部位的分布或云图，在哪些工况和时刻看？已有指定就摘录，其余由 AI 拟定。〕

**历史输出**　〔希望跟踪哪个点、区域或整体量的变化？已有采样要求就摘录，其余由 AI 拟定。〕

## 第二部分　AI 整理记录

由 AI 根据源项目书、附件与对话填写。事实注明来自哪里，查得或推导的建议值另记依据、适用条件和确认状态。

```yaml
格式版本: "0.5"
项目名称: null
研究方向: null
已知信息: []  # 每项写明 类别、内容、来源
报告问题: []  # 每项写明 编号、要求、判据、来源
文献与建模依据: []  # 对应问题、来源定位、筛选依据与年份、阅读范围、适用条件、建模选择、验证计划及待补项
拟用参数: []  # 每项写明 对象、参数、取值、单位、适用条件、来源、状态
分析方案:
  求解器: null
  方法: null
  建模与假设: []
  求解步长计划: []  # 各步的总时长或载荷范围、自动或固定、拟用增量及适用的上下限、单位、依据和复核指标
网格计划: []  # 区域、单元类型、阶次与公式、划分与细化、依据与验证、来源、状态
求解输出请求:
  场输出: []    # F 编号，区域内的空间分布及保存帧
  历史输出: []  # H 编号，测点、区域或整体量的历程及采样
  # 两类记录共用固定键，逐项独立填写
  # 编号、用途、变量与分量、单位、区域与输出位置、分析步、采样规则、取得方式、来源、状态
数据输出: []  # 对应问题、引用请求、数据、单位、区域与工况、提取与呈现
待补信息: []  # 每项写明 问题、影响的决定
工程师核对: {状态: 待确认, 意见: null}
```

各指标的用途、精度依据和再算条件可记入“报告问题”，初始网格与求解步长建议分别归入“网格计划”和“分析方案”。

单元记录包含适用区域、求解器单元名或预期代号、形状、阶次与关键公式。每项可注明选型依据、验证目标和来源。

F/H 的“用途”写报告问题编号或验证目的，方向量注明坐标系。图表的“引用请求”填编号列表，如 `[F1, H1]`。由场帧提取的历程在“取得方式”中引用来源及实际分辨率。整类停用时，在该类留一行“设置、原因、替代取数、来源、状态”，图表只引用仍生效的编号。

事实来源可写项目书章节、附件图号或工程师答复。物性注明出处和适用条件。尚待确定的值填 `null`。只将确实需要工程师答复的缺口列入“待补信息”。

求解前预览汇总拟用参数、单元选型、场输出和历史输出，供工程师一起核对。
